# Бриф кейса: LineSheet Loom в Juniper & Row Wholesale

> Все числа и факты ниже — синтетическая учебная легенда. Компания вымышленная, данные не являются рыночной статистикой. Они одинаковы во всех уроках и не меняются.

## Компания

Juniper & Row Wholesale — американский оптовый маркетплейс (B2B) товаров для дома и повседневной жизни. Поставщики присылают площадке обновления ассортимента, а отдел каталога переносит их в общий каталог.

| Показатель | Значение |
|---|---|
| Поставщики | 420 |
| Активные артикулы (SKU) | 85 000 |
| Пакеты обновлений от поставщиков в год | 1 200 — PDF, XLSX, CSV и сопроводительные письма |
| Новые или изменённые товарные строки в год | 60 000 |
| Отдел каталога | 14 сотрудников |
| Ручная обработка сегодня | в среднем 9,5 минуты на товарную строку |

## Пользователь и заказчик

* **Основной пользователь** — специалист отдела каталога (`Catalog Operations Specialist`). Разбирает материалы поставщиков, готовит строки каталога и проверяет рабочий результат.
* **Заказчик и владелец продукта** — директор отдела каталога (`Director of Catalog Operations`).

Остальные участники — владельцы данных, рисков и инцидентов, а также тот, кто принимает решение об импорте, — появятся в теме 4.5, когда речь пойдёт о правилах и контроле.

## Задача пользователя (JTBD)

> Когда поставщик присылает новый прайс-лист или обновление каталога, я хочу быстро получить проверяемый черновик товарных строк с источниками, противоречиями и недостающими данными, чтобы не переносить вручную десятки строк и не импортировать выдуманные цены или характеристики.

## Что делает LineSheet Loom

«Из разрозненных каталогов поставщиков в проверяемый черновик товарного каталога».

* **Вход:** подготовленный пакет файлов одного поставщика. Функция только читает файлы и ничего в них не меняет.
* **Выход:** внутренний нормализованный черновик товарных строк, то есть приведённый к единому формату.

Функция может:

* нормализовать только те значения, которые явно подтверждены источником
* предложить категорию товара
* сохранить неизвестное значение или противоречие между источниками, а не угадывать
* сформулировать вопрос проверяющему

## Поля черновика

Каждая товарная строка черновика состоит из одних и тех же полей. Названия полей технические и записаны по-английски — так они выглядят в самом черновике.

| Поле | Что означает |
|---|---|
| `supplier_id` | Идентификатор поставщика |
| `supplier_sku` | Артикул товара у поставщика |
| `title` | Название товара |
| `suggested_category` | Предложенная категория каталога |
| `material` | Материал |
| `color` | Цвет |
| `variant` | Вариант товара |
| `dimensions_raw` | Размеры в том виде, как они записаны в источнике |
| `dimensions_normalized` | Размеры, приведённые к единому формату |
| `dimension_unit` | Единица измерения размеров |
| `wholesale_price` | Оптовая цена |
| `price_basis` | К чему относится цена: к одной штуке, к упаковке и т. п. |
| `msrp_or_map` | Рекомендованная розничная цена (MSRP) или минимальная рекламируемая цена (MAP) |
| `currency` | Валюта |
| `pack_size` | Размер упаковки: количество единиц товара в ней |
| `moq` | Минимальная партия заказа |
| `lead_time_days` | Срок поставки в днях |
| `availability` | Доступность товара у поставщика |
| `field_status` | Статус значения — см. ниже |
| `source_ref` | Ссылка на источник: файл и конкретный лист, ячейка, страница или строка |
| `review_question` | Вопрос проверяющему |

`field_status` принимает только четыре значения:

| Значение | Смысл |
|---|---|
| `present` | Значение есть в источнике и перенесено в черновик |
| `unknown` | В источнике нет основания для значения |
| `conflict` | Источники противоречат друг другу |
| `needs_review` | Значение требует проверки человеком |

## Границы: чего LineSheet Loom не делает

* не публикует товары
* не импортирует строки в каталог
* не меняет цены и остатки
* не придумывает отсутствующие значения
* не конвертирует валюту без заданного правила
* не решает, допустим ли товар к продаже
* не выбирает между противоречащими источниками без правила
* не смешивает товары или поставщиков
* не общается с поставщиком
* не вызывает внешние инструменты

Банковские данные, учётные данные для входа в системы, документы личности и нерелевантные персональные данные не попадают в результат.

## Сильная альтернатива без ИИ

Structured Intake — первичный структурированный вход: обязательный шаблон для поставщиков, портал с проверкой заполнения, словари категорий и единиц, детерминированные правила цен и упаковок, нечёткое сопоставление записей и ручная очередь исключений. Подробнее — в `03-current-process-and-alternative.md`.
